Diagnostics

Leave this off for normal use. The decoder has not been confirmed on hardware, so if a reading looks wrong or the link never reaches ready, probe mode connects, enumerates the GATT services and characteristics, subscribes to anything that notifies, and hex-dumps what arrives to the Status tab's log — without decoding it. See docs/PROTOCOL.md for what to look for.

NUT server

Sets ups.realpower.nominal, the 100% mark for ups.load. 200 W on an Elite 10.

Sets battery.runtime.low. Raises LB at this or the low-battery %, whichever comes first.

Clients connect with upsc bluetti@<ip>.

Credentials

These gate LOGIN and PRIMARY — the commands upsmon uses to coordinate shutdown. Reading values stays anonymous, as it is on a normal NUT server, because upsc has no way to send credentials.

In upsmon.conf:
MONITOR bluetti@<ip> 1 upsmon <password> slave

Upload an esp32-nut-bluetti-<version>.bin you already have. Use this when the bridge has no route out, or to install a build that was never released.

Status LED

The onboard addressable LED shows the bridge's state at a glance: red while starting up, green once it is talking to the Bluetti unit over Bluetooth.

If nothing lights, the pin is probably wrong for your board. Common values are 48, 38 and 21; set -1 to turn it off. Change it, then Test flashes red / green / blue on that pin.
